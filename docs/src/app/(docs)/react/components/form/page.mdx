## Anatomy

Form is composed together with [Field](/react/components/field). Import the components and place them together:

```jsx title="Anatomy"
import { Field } from '@base-ui/react/field';
import { Form } from '@base-ui/react/form';

<Form>
  <Field.Root>
    <Field.Label />
    <Field.Control />
    <Field.Error />
  </Field.Root>
</Form>;
```

### Submit form values as a JavaScript object

You can use `onFormSubmit` instead of the native `onSubmit` to access form values as a JavaScript object. This is useful when you need to transform the values before submission, or integrate with 3rd party APIs.

```tsx title="Submission using onFormSubmit"
<Form
  onFormSubmit={async (formValues: { id: string; quantity: number }) => {
    const payload = {
      product_id: formValues.id,
      order_quantity: formValues.quantity,
    };

    const response = await fetch('https://api.example.com', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(payload),
    });
  }}
/>
```

When used, `preventDefault` is called on the native submit event.

## Accessibility

- **Focus moves to the first invalid field on a failed submit**, and to the first field marked invalid by an updated `errors` prop—so screen reader and keyboard users land directly on the problem instead of having to search the form. `<input>` fields also have their value selected for quick correction.
- **Native browser validation UI is disabled** (`noValidate`) in favor of Base UI's own validation, which surfaces errors through each field's `aria-invalid` and `<Field.Error>`—see [Field's accessibility notes](/react/components/field#accessibility) for how that wiring works.
- Errors passed through the `errors` prop are matched to fields by their `name`, so every field that can report a server-side error needs a `name` that matches its key in `errors`.
