## Anatomy

Import the component and assemble its parts:

```jsx title="Anatomy"
import { Accordion } from '@base-ui/react/accordion';

<Accordion.Root>
  <Accordion.Item>
    <Accordion.Trigger />
    <Accordion.Panel />
  </Accordion.Item>
</Accordion.Root>;
```

- `Accordion.Item` renders a native `<details>` element.
- `Accordion.Trigger` renders its `<summary>` — the control that labels and toggles the panel.
- `Accordion.Panel` renders the `<details>` content, so it stays in the DOM while closed and can be animated with the `::details-content` pseudo-element.

## Examples

### Open multiple panels

By default only one panel stays open at a time: each item's `<details>` shares a `name`, so the browser closes the others natively. Set the `multiple` prop to let several panels stay open at once (the shared `name` is dropped).

## Accessibility

- **Native semantics**: each `Accordion.Item` is a `<details>` and each `Accordion.Trigger` is its `<summary>`, so the browser provides the disclosure role and announces the expanded/collapsed state — no `aria-expanded`, `aria-controls`, or `role` attributes are added.
- **Keyboard interactions** (all built in):
  - <kbd>Enter</kbd> / <kbd>Space</kbd> — toggles the focused trigger's panel open or closed.
  - <kbd>Tab</kbd> / <kbd>Shift+Tab</kbd> — moves between triggers in the normal tab order.
- **Exclusive open state**: single-open behavior comes from the shared `name` on each `<details>`, so it keeps working even before JavaScript loads.
- **Find in page**: because closed panels stay in the DOM, the browser's find-in-page can match hidden text and open the corresponding item automatically.
- **Disabled items**: a disabled trigger keeps `aria-disabled` (staying focusable and discoverable) instead of being removed from the tab order, and its toggle is suppressed.
